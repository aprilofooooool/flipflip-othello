## 2. 判定（±30% の範囲は JOY 138〜256、PANIC 232〜430）

- standard: そのまま `Otc.Const`（JOY 197 / PANIC 331 / ADVANTAGE 197）。
- mini: 両方とも ±30% に収まるので共通値（RuleSet に `thresholds` を持たない）。
- anti: PANIC が外れる → RuleSet に `thresholds: { JOY_DELTA: 236, PANIC_DELTA: 475, ADVANTAGE_EVAL: 236 }`。
- mini-anti: 両方とも外れる → `thresholds: { JOY_DELTA: 320, PANIC_DELTA: 646, ADVANTAGE_EVAL: 320 }`。
- 外れたルールには、範囲内だった値（anti の JOY）も含めて 3 つとも計測値を書く。理由: 1 つのルールのしきい値を同じ計測から揃えるため。
- ADVANTAGE_EVAL は今の決め方（JOY_DELTA と同じ値から始める）に合わせて、そのルールの JOY_DELTA とする。
- 参照は `Otc.Reaction.threshold(ruleSetId, key)` を通す（RuleSet の値があればそれ、無ければ `Otc.Const[key]`）。

## 3. CPU の強さ

- ツール: `node tests/tools/measure-strength.js 40 20261104 <ruleSetId>`（ruleSetId を省くと 4 ルールすべて）
- 条件: 各組み合わせ 40 局、先後入れ替えて半々、`timeMs: Infinity`、seed 20261104（組み合わせごとに同じ seed で作り直す）。勝率 = 勝ち / 局数（引き分けは勝ちに数えない）。
- 合格条件: ふつう・つよいがやさしいに勝ち越す（勝率 > 50%）。

| ルール | ふつう 対 やさしい | つよい 対 やさしい | ふつう 対 つよい（記録のみ） |
|---|---|---|---|
| standard | 40-0-0（100%）合格 | 40-0-0（100%）合格 | 0-0-40（0%） |
| anti | 38-0-2（95%）合格 | 40-0-0（100%）合格 | 0-0-40（0%） |
| mini | 39-0-1（97.5%）合格 | 40-0-0（100%）合格 | 0-0-40（0%） |
| mini-anti | 35-1-4（87.5%）合格 | 38-1-1（95%）合格 | 0-0-40（0%） |

（勝ち-引き分け-負け。ふつう 対 つよい は両方ともランダム手が無いので、実際には先後 2 通りの局をくり返している。）

- 全ルール合格。misere の評価（Task 2）は変えていない。
- 実行時間: anti の「つよい 対 やさしい」が 563 秒でいちばん長い（8x8 で終盤 12 空きまで読み切るため）。

## 4. 補足

- アンチ（anti / mini-anti）の終盤は Panic に偏り（14.6% / 16.9%）、Joy はほとんど出ない（0.6%）。mini-anti の序盤は Joy が 17.6% と多い。しきい値をルールごとにしても、フェーズによる偏りは残る。フェーズ別しきい値は今回の範囲（±30% の判定）に含めていない。
