<technical_constraints>
## 使用技術
- Pure HTML5 / CSS3 / Vanilla JavaScript（ES2017 以上）のみ。フレームワーク・ライブラリ・トランスパイラ・バンドラ・npm パッケージは使わない。
- 外部 CDN・Google Fonts・外部 API・アナリティクスは使わない。実行時のネットワーク通信はゼロ（同一フォルダ内の相対パス読み込みのみ）。
- フォントはシステムフォントスタック（丸ゴシック系を優先：`"Hiragino Maru Gothic ProN", "M PLUS Rounded 1c", "Yu Gothic UI", system-ui, sans-serif` など）。

## file:// 直開きでの制約（重要。必ず守る）
`index.html` をローカルで直接開く（`file://`）と、Chrome では以下が動作しない。設計時に必ず回避すること。
- `<script type="module">`（ES Modules の import/export）→ **使わない**。通常の `<script src="...">` を依存順に並べ、単一のグローバル名前空間（例：`window.Otc`）に各モジュールを登録する IIFE 形式とする。
- `fetch()` / `XMLHttpRequest` による JSON・テキスト読み込み → **使わない**。キャラクター定義・セリフ・ルール定義などの設定データは `.js` ファイル（名前空間への代入）として持つ。
- Web Worker（別ファイル）→ 使わない。AI 探索はメインスレッドで実行し、思考時間上限を設けて UI を固めない（探索開始前に描画のための待ちを入れる、反復深化＋時間打ち切りなど）。
- Canvas に画像を描いて `getImageData` 等で読み出すこと（tainted canvas になる）→ しない。石の画像表示は `<img>` または CSS `background-image` ＋ `border-radius: 50%` / `clip-path` で行う。
- Service Worker / PWA → 対象外。

## GitHub Pages 対応
- すべて相対パス。ルート直下に `index.html` と `.nojekyll` を置く。
- **ファイル名・フォルダ名はすべて小文字の英数字とハイフン**。Windows は大文字小文字を区別しないが GitHub Pages（Linux）は区別するため、参照とファイル名の大文字小文字を完全一致させる（テストで検査する）。
- 日本語ファイル名・スペースを含むファイル名は使わない。

## 対応環境と優先度
- 最優先：iOS Safari（iOS 17 以降、iPhone 縦向き。幅 375px〜430px）。
- 次点：PC の Chrome 最新版（幅 1024px 以上）。
- 両立が困難な場合は iOS を優先し、そのトレードオフを設計書に記録する。
- iOS 対応で必ず入れるもの：
  - `viewport-fit=cover` と `env(safe-area-inset-*)`（ノッチ・ホームバー回避）
  - 高さは `100dvh`（`100vh` だけに頼らない）
  - `touch-action: manipulation`（ダブルタップズーム防止）、盤面での長押しメニュー・テキスト選択の抑止（`-webkit-touch-callout: none` / `user-select: none`）
  - タップ領域は 44x44px 以上。hover 前提の操作を作らない
  - 横向きでもレイアウトが崩れない（盤面とキャラ表示が横並びになる等）
- 盤面は画面幅に合わせて正方形を維持し、縦スクロールなしで盤面・両キャラ・操作ボタンが 1 画面に収まること（iPhone SE 幅 375x667 でも）。

## UI 言語
- 画面上の文言はすべてひらがな中心の子供向けの易しい日本語。コード・識別子・ファイル名・コメントは英語でよい。

## 音（Web Audio API）
- 外部音声ファイル（MP3/WAV 等）は使わない。`AudioContext` / `OscillatorNode` / `GainNode`（必要なら `BiquadFilterNode`）で動的合成する。
- 合成する音：石を置く音、石が返る音（返る枚数に応じて連続「ぱたぱた」音）、リアクション発生音（感情ごとに音色を変える）、パス音、ゲーム終了音（勝ち／負け／引き分けで変える）、ボタン操作音。
- iOS は最初のユーザー操作（タップ）時に `AudioContext` を生成または `resume()` する。無操作で鳴らそうとしない。
- 画面上に「おと ON/OFF」切替を置き、設定は保存する。iOS のマナーモード時に鳴らない場合がある旨はヘルプ等に記載する。

## 永続化
- `localStorage` に保存するのは設定のみ（前回選んだキャラ・モード・難易度・おと・アシスト）。読み書きは try/catch で囲み、使えない環境でも動作すること。
- 対局途中の保存・再開を入れるかは `<open_questions>` で確認する。
</technical_constraints>

- **ファイルを置き換えるだけで反映される**こと（コード変更不要）。拡張子や個別ファイル名を変えたい場合はキャラクター定義ファイル 1 か所の修正で済むこと。

  1. 指定感情の画像 → 2. `normal` 画像 → 3. キャラクター定義のテーマカラーで描いた CSS ディスク（顔文字・イニシャル等のポップな表現）
- 現時点で正式画像は未支給の可能性がある。**仮画像として、オリジナルの簡易 SVG（キャラごとの色・頭文字・感情を表す顔文字程度）を同じ規則で生成して置く**。公式イラストを模写・トレースしたものは作らない。
- `assets/README.md` に「画像の差し替え手順」「キャラクター追加手順」を日本語で書く。

## 石（ディスク）表示
- プレイヤーが選んだキャラクター画像が、盤上の石そのものとして円形にフィットして描画されること。
- 石が返る際は「ぱたぱた」の名前どおり、3D 回転（`rotateY` ＋ `backface-visibility`）で表裏のキャラ画像が入れ替わるアニメーションにする。複数枚は置いた位置から近い順に少しずつ遅らせて返す。
- どちらの石か一目で区別できるよう、石の外周にプレイヤーごとのテーマカラーのリングを付ける（画像が似ていても判別可能にする）。
- 盤上の石は原則 `disc`（または `normal`）画像。盤上の石にも感情を反映するかは `<open_questions>` で確認する。

## キャラクター定義（データ駆動）
- `js/data/characters.js` のような単一データファイルに、キャラごとに以下を持つ：
  `id`, 表示名, テーマカラー（主色・副色）, 画像パス規則, 一人称, 語尾・口癖, 感情別・状況別セリフ配列。
- キャラクター追加は「アセットフォルダ追加＋定義ファイルへの 1 エントリ追加」だけで完了し、選択画面にも自動で並ぶこと。

## セリフ（口調・語尾）
- 各キャラの一人称・語尾・口癖は、**公式サイト等の信頼できる情報源を Web 検索で調べてから**設計する。
  - 調査結果を `.claude/docs/research/YYYY-MM-DD-character-voice.md` に、根拠 URL・確認日付きで記録する。
  - 根拠が見つからない項目は「要確認」と明記し、ユーザーに確認する。推測で断定しない。
  - 公式のセリフ文をそのまま転載しない。口調・語尾を踏まえたオリジナルのセリフを作る。
- セリフを出す状況（最低限）：対局開始、自分の手番開始、考え中、良い手を打った、四隅を取った、四隅を取られた、たくさん返された、パス、劣勢、優勢、勝ち、負け、引き分け。
- 各状況×キャラで 3 種類以上。ランダム選択だが直前と同じセリフは連続させない。
- 吹き出しは子ども向けに短く（目安 20 文字以内）、ひらがな多めにする。

<functional_specifications>
## 1. トップ画面（設定画面）
トップ画面とプレイ画面は明確に分離する（同一 HTML 内の画面切替でよい。ブラウザの戻る操作の扱いは設計書に記載）。

構成要素：
- タイトルロゴ「ぱたぱた！オセロっち」（CSS で作るポップなロゴ。画像化してassetsから差し替えに対応する）
- ゲームモード：「ひとりであそぶ」（vs CPU）／「ふたりであそぶ」（1 台の端末で交互に操作）
- キャラクター選択：
  - プレイヤー 1・プレイヤー 2 それぞれ、4 キャラから選ぶ（画像付きカード）。
  - 同じキャラは選べない（選択済みはグレーアウト）。
  - vs CPU：プレイヤーが選んだキャラ以外から CPU キャラをランダムに決定し、スタート前に表示する（「CPU：○○っち」）。
- 先手・後手：先手（黒番）をどちらにするか選べる（「じぶんがさき／CPUがさき」「1Pがさき／2Pがさき」「ランダム」）。
- CPU の強さ（ひとりモードのみ）：「やさしい」「ふつう」「つよい」。
- ハンディキャップ（ふたりモードのみ。設計上は CPU 戦にも流用可能な作りにする）：
  - 「なし（通常配置）」に加え、日本オセロ連盟などの公式ハンデ戦ルール（弱い側にあらかじめ隅の石を与える方式等）を **公式情報で確認してから** 実装する。確認結果は research に記録する。
  - 「石数オフセット」のように公式に存在しないハンデを入れるかは `<open_questions>` で確認する。入れる場合は「オリジナルルール」と明示して公式ハンデと区別する。
  - ハンデを誰に適用するか（1P／2P）を選べること。
- 「あそびかた」（ルール説明）ボタン：簡単な日本語説明をモーダルで表示。
- 「スタート」ボタン：必須項目が未選択なら押せない（理由を表示）。

## 2. ゲームプレイ画面
レイアウト：
- 盤面の外（縦向きは上下、横向き・PC は左右）に両プレイヤーのキャラクター画像を常時表示する。
- 各キャラ表示には：キャラ画像（現在の感情）、名前、石数、手番インジケータ、吹き出し。
- 現在の手番が誰かがはっきり分かること（手番側を拡大・光らせる等）。
- 操作ボタン：もどす（Undo）／すすめる（Redo）／アシスト ON/OFF／おと ON/OFF／リセット（最初から）／トップへもどる。リセットとトップへもどるは確認ダイアログを出す。

ルール（標準 8x8・公式ルール）：
- 初期配置：中央 4 マスに公式どおり配置。先手は黒。
- 8 方向の挟み込み判定。合法手のマスにのみ置ける。合法手マスは小さなドットで常に表示する（表示 ON/OFF を入れるかは任意）。
- 合法手がない場合は自動パス。「○○っちはパス！」を一定時間表示してから手番を移す（タップで早送り可）。
- 両者とも合法手がない、または盤面が埋まったら終局。石数で勝敗判定。
- 終局画面：結果（勝ち／負け／引き分け、石数）、勝者は Joy・敗者は Sadness、「もういちど」「トップへ」ボタン。

CPU の思考演出：
- CPU 手番では即座に打たず、ランダムな待ち時間（0.8〜1.5 秒）を入れる。その間 CPU キャラは Thinking 画像・考え中セリフ。
- 実際の探索時間がこの待ちより長い場合は探索完了まで待つ（待ちは「最低表示時間」として扱う）。
- CPU 思考中はプレイヤーの盤面操作を受け付けない。Undo・トップへもどるは受け付け、押されたら思考をキャンセルする。

プレイヤーの長考演出：
- 人間の手番で一定時間（初期値 5 秒、定数で変更可能）操作がなければ、そのキャラを Thinking に切り替える。打ったら解除。

アシスト機能（1P・2P 共通）：
- ON の間、現在手番のプレイヤーにとっての最善手（AI の評価で 1 位の手）を盤面上でハイライトする（キラキラ枠など）。
- アシスト用の探索深さは固定値（例：「ふつう」相当）とし、CPU の強さ設定とは独立させる。
- ON/OFF はプレイ中いつでも切替可能で、設定は保存する。

履歴管理：
- 無制限の Undo／Redo。ゲーム状態のスナップショット（盤面・手番・パス状態・ハンデ）を履歴として保持する。
- vs CPU 時の Undo は「プレイヤーの直前の手番まで」戻す（CPU の手とプレイヤーの手をまとめて戻す）。Redo も同じ単位。
- 新しい手を打ったら Redo 履歴は破棄する。
- Undo／Redo 後もキャラの感情・石数・合法手表示・アシスト表示が正しく再計算されること。
- Undo／Redo 時はリアクション演出を発火させない。

## 3. 動的リアクションシステム（感情と演出）
- 毎手、手を打った側から見た評価値を記録し、変化量 ΔE と盤面イベントから両キャラの感情を決める。打った側だけでなく相手側も反応する（例：隅を取った側が Joy、取られた側が Anger）。
- 判定ルール（しきい値はすべて定数ファイルで調整可能にする）：

| 感情 | 発火条件 | 演出 |
|---|---|---|
| 歓喜 Joy | 評価値の大幅上昇、または四隅の獲得 | 金色の花火パーティクル、アバターのバウンド |
| 怒り Anger | 相手に四隅を取られた | 画面の赤フラッシュ、怒りマーク（💢 風の CSS 表現） |
| 悲しみ Sadness | 1 手で 5 枚以上返された | 雨のエフェクトレイヤー、暗いオーバーレイ |
| パニック Panic | 評価値の大幅下落、または強制パス | 画面の縦揺れ、冷や汗パーティクル |
| 考え中 Thinking | CPU 思考中／プレイヤー長考 | 考え中の吹き出し（「…」アニメーション） |
| 通常 Normal | 上記以外。演出終了後に戻る | — |

- 同時に複数の条件を満たした場合の優先順位を設計書で定義する（初期案：Anger ＞ Panic ＞ Sadness ＞ Joy。ユーザーに確認する）。
- 演出は「ゆっくり目」：1 演出あたり 1.5〜2.5 秒程度。演出中も次の操作は受け付ける（演出が終わるまで待たせない）。新しい演出が来たら古い演出は自然に終了させる。
- 感情画像は演出終了後、一定時間（例：2 秒）で Normal に戻る。
- アニメーションは `transform` / `opacity` 中心で、iPhone で 60fps を維持する。パーティクル数には上限を設ける。
- `prefers-reduced-motion: reduce` の環境では、画面揺れ・フラッシュを弱めた代替表現にする（光過敏への配慮）。
</functional_specifications>

<ai_specification>
## 探索
- Alpha-Beta 枝刈り付き Minimax（Negamax 形式可）。パスを手として正しく扱うこと（片側パス時は手番交代して探索継続、両者パスで終局評価）。
- 指し手オーダリング：隅を優先、X 打ち（隅の斜め隣）・C 打ち（隅の隣）を後回し、浅い探索結果や位置重みで並べ替え。
- 反復深化＋時間上限（iPhone でも 1 手あたり探索 1.5 秒以内を目安）。時間切れ時は直前に完了した深さの最善手を返す。
- 終盤（空きマスが一定数以下、例：10〜12）は石数差による完全読み。

## 評価関数
- 位置重みマトリクス（盤面サイズから生成できる形にする。8x8 は定番の重み表を初期値とする）
- 着手可能手数（Mobility）の差
- 確定石（隅から連なる、もう返らない石）の数
- 終盤は石数差の比重を上げる（序盤・中盤・終盤で重みを変える）
- 評価値は「指定プレイヤー視点」で返す（ReactionEngine が両者視点で使うため）。

## 難易度
| 表示 | 初期案 |
|---|---|
| やさしい | 深さ 1〜2、一定確率でランダム手（隅を逃すこともある） |
| ふつう | 深さ 3〜4 |
| つよい | 深さ 5〜6 ＋ 終盤完全読み |

数値は定数で調整可能にし、実機（iPhone）で待ち時間が長すぎないことを確認して決める。
</ai_specification>

<architecture>
## 基本方針
- 単一グローバル名前空間（例：`window.Otc`）に各モジュールを登録する。読み込み順は `index.html` の `<script>` 並びで管理する。
- **ロジック層（ルール・盤面・AI・リアクション判定・履歴）は DOM に一切触れない純粋関数／クラス**とし、ブラウザと Node.js の両方でテストできるようにする（`module.exports` があれば併せて公開する UMD 風の書き方）。
- モジュール間の通知は小さなイベント発行の仕組み（例：`placed` / `flipped` / `passed` / `turnChanged` / `gameOver` / `reaction`）で疎結合にする。過剰な抽象化はしない。

## モジュール構成（ベース案。brainstorming で確定させる）
| モジュール | 責務 | DOM |
|---|---|---|
| `ReversiEngine` | 盤面状態・合法手判定・着手と反転・パス・終局判定・スコア。ルール定義（RuleSet）を受け取って動く | 触らない |
| `ReversiAI` | Minimax＋Alpha-Beta・評価関数・指し手オーダリング・難易度設定（ReversiEngine から分離し、ルール追加時に影響範囲を限定） | 触らない |
| `GameController` | 1 局の進行（手番管理・CPU 手番のスケジュール・思考キャンセル・Undo/Redo 履歴・設定の受け渡し）。各モジュールの橋渡し役 | 触らない |
| `ReactionEngine` | 評価値の差分計算・盤面イベントから感情を判定（判定部は純粋関数）。演出の発火指示をイベントで出す | 判定部は触らない |
| `CharacterManager` | キャラ定義の読み込み・感情別画像の解決とフォールバック・石への画像適用・セリフ選択 | 画像適用部のみ |
| `UIManager` | 画面切替・DOM 描画・CSS アニメーション制御・アシスト表示・ダイアログ | 触る |
| `SoundSynthesizer` | Web Audio API による効果音合成・ON/OFF | 触らない |

## 拡張性の要件（将来対応を想定した設計）
- **ルール追加**：`RuleSet` オブジェクト（盤面サイズ・初期配置・ハンデ適用・合法手判定・終局条件・勝敗判定）を定義ファイルに追加するだけで新ルールを選択可能にする。標準ルールも RuleSet の 1 つとして実装する。
- **盤面サイズ追加**：盤面サイズを定数に埋め込まない。盤面表現・描画・位置重み・テストを N×N（偶数、例：6x6 / 10x10）でも動く作りにする。初期リリースで選択肢に出すのは 8x8 のみ。
- **キャラ追加**：`<character_and_assets>` のとおりデータ追加のみで完結。
- **バージョン表記**：`js/config/version.js` に `APP_VERSION` を置き、トップ画面フッターに表示。`CHANGELOG.md` を作る。
- 拡張ポイント（どのファイルに何を足せば何が増えるか）を設計書と `README.md` に一覧で書く。

<design_guidelines>
- たまごっちらしい世界観：パステル＋ビビッドの差し色、丸み（大きめの角丸・丸ボタン）、太めの縁取り、ドット／たまご型のモチーフ、ぷにっとしたボタン押下アニメーション。
- 盤面も木目ではなくポップな配色（例：ミントグリーンの盤、白い区切り線）。ただし石とのコントラストを確保する。
- 配色・角丸・影・アニメーション時間は CSS カスタムプロパティで一元管理し、テーマ変更が 1 か所で済むようにする。
- 文字はひらがな多め・短く。子どもでも分かる表現にする。
- 文字と背景のコントラストは WCAG AA を目安にする。主要ボタンには `aria-label` を付ける。
- PC では盤面をマウスでクリックして操作できる（キーボード操作は任意）。
</design_guidelines>

<verification_criteria>
## 自動テスト（Claude が実行し、結果を報告に記録する）
テストは `tests/test.html`（ブラウザ直開き）で実行でき、Node.js が使える場合は `node tests/run-node.js` でも同じテストが通ること。

ReversiEngine：
- 初期局面の合法手が 4 つで、位置が公式どおり。
- perft（指定手数まで全合法手を展開した局面数。パスなし範囲）が既知値と一致：深さ 1=4、2=12、3=56、4=244、5=1396、6=8200。
- 8 方向それぞれの反転、端・角での反転、複数方向同時反転。
- パス局面：片側のみ合法手なし→パス、両者なし→終局。盤面が埋まった終局。
- 勝敗判定（勝ち・負け・引き分け）。
- ハンデ適用後の初期局面が仕様どおり。
- 6x6・10x10 の RuleSet でも合法手判定と終局判定が正しく動く（拡張性の担保）。

ReversiAI：
- 同一局面・同一深さで、Alpha-Beta の結果（評価値）が枝刈りなしの Minimax と一致する（ランダム局面 50 件以上）。
- 隅が取れる局面で「つよい」は隅を選ぶ。
- 終盤完全読みの結果が全探索の正解と一致。
- 「つよい」でも 1 手の探索が設定時間上限を超えない（Node 上で計測。実機確認は手動テストで行う）。
- パスを含む局面で例外を出さない。

GameController / 履歴：
- Undo→Redo で完全に同じ状態に戻る（盤面・手番・パス状態）。
- vs CPU の Undo がプレイヤー手番まで戻る。新しい手で Redo 履歴が消える。
- CPU 思考中の Undo でも状態が壊れない（思考結果が後から適用されない）。

ReactionEngine：
- 表の各発火条件で期待の感情が返る。複数条件時は優先順位どおり。打った側と相手側の両方の感情が返る。
- Undo/Redo では発火しない。

CharacterManager：
- 画像パスの解決が規則どおり。感情画像なし→normal→CSS ディスクの順にフォールバックする（存在しないパスで検証）。
- 同じキャラを両プレイヤーに選べない。CPU キャラはプレイヤー以外から選ばれる（多数回試行）。
- セリフが直前と連続しない。全キャラ×全状況のセリフが 3 種類以上ある（データ検査）。

静的検査：
- `index.html`・CSS・JS から参照しているすべての相対パスが実在し、**大文字小文字まで一致**する（スクリプトで検査）。
- `type="module"`、`fetch(`、`import `、`new Worker(`、`http://`・`https://` で始まる外部参照がソース中に無い（README 内のリンクは除く）。

## E2E 確認（Claude が Playwright MCP 等で実行）
- `file://` で `index.html` を開き、トップ→スタート→数手プレイ→Undo/Redo→終局まで進められる。コンソールエラー 0 件、外部ホストへのネットワーク要求 0 件。
- ローカル HTTP サーバー経由（GitHub Pages 相当）でも同じく動く。
- iPhone 相当（375x667、390x844、430x932 の縦横）と PC（1280x800、1920x1080）でスクリーンショットを撮り、盤面・両キャラ・ボタンがスクロールなしで収まり、はみ出し・重なりがないことを確認する。スクリーンショットは `.claude/docs/reports/` 配下に保存する。
- vs CPU を最後まで自動で進めて（プレイヤー側もランダム手）、終局画面が出ることを確認する。
