# 派生ルール（6x6 盤・アンチオセロ）設計書

- 作成: 2026-11-04
- 前提資料: `.claude/docs/research/2026-11-02-othello-variants-board.md`、`.claude/docs/research/2026-11-02-othello-variants-rules.md`
- 本体の設計: `.claude/docs/specs/2026-10-29-patapata-othellocchi-design.md`（以下「本体設計」。技術制約 2 章はそのまま適用）
- 表記: 【ユーザー決定】＝ユーザーが決めたこと／【Claude判断】＝Claude が決めたこと（ユーザーが読んで修正できる）

## 1. 目的と方針

### 1.1 何を作るか
設定画面で「盤の大きさ」と「勝ち方」を組み合わせて選べるようにする。
- 盤の大きさ: 8x8（今まで）／6x6（ミニ）
- 勝ち方: ふつう（石が多い方が勝ち）／アンチ（石が少ない方が勝ち）

### 1.2 なぜ作るか
- いつものオセロに飽きたとき、同じアプリで違う遊び方を楽しめるようにする。
- 後で作る「4人対戦モード」（別の設計書）の土台を整える。具体的には「ルールを選ぶ画面」と「CPU とキャラの反応がルール定義に従う作り」を、ここで先に作っておく。

### 1.3 実施順【ユーザー決定】
① 6x6 → ② アンチオセロ → ③ 4人対戦（別の設計書）。この設計書は①②を扱う。

### 1.4 ゴール
- 4つの組み合わせ（8x8ふつう／8x8アンチ／6x6ふつう／6x6アンチ）がすべて遊べる。対象は 1人用（CPU 対戦）と 2人用の両方。
- CPU は、選んだ勝ち方で勝とうとして打つ。
- キャラクターの喜怒哀楽は、選んだ勝ち方の損得に合わせて出る。

### 1.5 非ゴール（やらない）
- 10x10（グランドオセロ）、エイトスターズ、六角盤などの盤。10x10 は初期配置が確認できていないため保留。
- 置けないマス（壁）の扱い。
- 4人対戦（③で別に設計する）。
- 6x6 用やアンチ用の新しいセリフの追加。セリフの選び方は、今の感情からの選択をそのまま使う。

### 1.6 アンチゴール（動いても失敗とみなす）
- アンチなのに、CPU が石を多く取ろうとする。またはキャラが「たくさん取れて喜ぶ」。
- 画面の勝敗表示と CPU の読みで、勝ち負けの判定が食い違う。
- ふつうの 8x8 の遊び心地（CPU の強さ・反応の出方）が、今より変わってしまう。

## 2. ルール（出典つき）

### 2.1 6x6 盤
- 盤 6x6。初期配置は中央4マスで、8x8 と同じ並び（c3/d4=白、d3/c4=黒）。今の `initialDiscs(size)` がそのまま使える。
- 着手・裏返し・パス・終局・勝敗は 8x8 と同じ（8方向）。
- 出典: メガハウス公式の6x6商品（販売終了）。Feinstein 1993 の完全解析（後手が 20-16 で勝ち）。research 資料の該当節を参照。

### 2.2 アンチオセロ（石が少ない方が勝ち）
- 着手・裏返し・パス・終局は、ふつうのルールと同じ。変わるのは勝敗だけ。
- 出典: 英語版 Wikipedia（Reversed Reversi）、GNOME Iagno の `--reverse` オプション。
- **空きマスの扱い**【Claude判断】: 出典に決まりがない。終局時の空きマスはどちらにも足さず、盤上の石の数だけで比べる。少ない方が勝ち、同数なら引き分け。
- ふつうのルールの空きマスの扱いは、今のまま変えない。

### 2.3 組み合わせ
- 盤の大きさと勝ち方は独立して選べる（4通り）【ユーザー決定】。
- **ハンデ**【Claude判断】: 「8x8・ふつう」のときだけ選べる。それ以外ではハンデ欄を隠し、ハンデ 0 として始める。理由: 日本オセロ連盟のハンデ規定は 8x8 のふつうのルールが前提で、他のルールでの決まりが見つからない。

## 3. データの持ち方

### 3.1 RuleSet
- 今の仕組み（`js/data/rulesets.js` の RuleSet と、エンジンの任意フック `legalMoves` / `isGameOver` / `result`）を使う。新しい抽象化は作らない。
- 4つの組み合わせを、それぞれ1つの RuleSet として登録する。id の例: `standard`（今の id のまま。保存データとの互換のため変えない）、`anti`、`mini`、`mini-anti`。
- アンチは `result` フックで勝敗を逆にする。
- RuleSet に「勝ち方」を表す値を持たせる（例: `misere: true`）。CPU・反応・結果表示がこの値を見て、勝敗の向きを決める。

### 3.2 設定
- 設定画面の状態に「盤の大きさ」と「勝ち方」の2つを持ち、ゲーム開始時に RuleSet の id に変換して GameController に渡す。
- 保存は、今の設定保存（localStorage、try/catch つき）に足す。保存値が不正なら 8x8・ふつうに戻す。
- 途中保存されたゲーム（`ruleSetId` を持つ）は、そのルールのまま再開できること。今の検証（`game-controller.js:103`）は `RuleSets.get` で id を確かめているので、新しい id も通る。

## 4. CPU（`js/engine/reversi-ai.js`）

### 4.1 ルール定義に従わせる（必須）
今の CPU は `E.flipsFor` を直接呼び、終局と勝敗も独自に判定している（`reversi-ai.js:76`、`:148`、`:184-199`。勝敗の値は `:123-127`、`:196`）。これを次のように直す。
- 合法手の生成と終局判定は、RuleSet のフックを通る経路（`E.legalMoves` / `E.isGameOver` 相当）にそろえる。
- 終局の値は、RuleSet の勝ち方に従う。アンチでは石差の符号を逆にする（自分の石が少ないほど高い値）。
- 速度の都合で直接呼び出しを残す場合は、「RuleSet にフックが無いときだけ直接呼ぶ」形にして、結果が同じであることをテストで確かめる。速度が今より大きく落ちてはいけない（つよい CPU の1手の時間上限は今のまま）。

### 4.2 アンチの評価関数【Claude判断】
- 位置重み・確定石・石差の項は符号を逆にする（隅を取るのは損、石が多いのは損）。
- 着手可能数（mobility）の項は、アンチでも符号を変えない。理由: 自分の打てる手が多いほど、損な手を避けやすいため。
- 強さの調整は、自動対局で確かめる程度とする。アンチの CPU がとても強い必要はない。【Claude判断】合格条件は「つよい・ふつうが、やさしいに勝ち越す」こと（満たさなければ評価関数を直す）。ふつうとつよいの差は記録するだけで、互角でも合格とする。結果は `.claude/docs/reports/` に記録する。

### 4.3 6x6 での調整【Claude判断】
- 局面フェーズの区切り（`constants.js:19-21` の `minEmpties: 41 / 15`）と、終盤の完全読みを始める空き数（`constants.js:66-69` の `endgameEmpties: 8 / 12`）は 64 マス前提。6x6（36マス）では、盤のマス数に比例させた値を使う（例: 41/64 → 23、15/64 → 8）。終盤完全読みの空き数は、8x8 と同じ値のままでよい（6x6 なら早く読み切れる）。
- 位置重みは、今の `positionWeights(size)`（隅・C・X・辺・内側の分類）をそのまま使う。
- 6x6 の「つよい」はほぼ完璧に打つ可能性がある。これは許容する。

## 5. キャラクターの反応（`js/game/reaction-engine.js`）

### 5.1 方針【ユーザー決定】
アンチのとき、反応は「アンチの損得」に合わせて変わる。

### 5.2 具体的な規則【Claude判断】
今の発火条件（本体設計 7.2）を、アンチでは次のように読み替える。

| 条件 | ふつう（今のまま） | アンチ |
|---|---|---|
| 隅を取った | 打った側 Joy／相手 Anger | 打った側 Panic／相手 Joy |
| 一度にたくさん返した（`SADNESS_FLIPS` 以上） | 相手 Sadness | 打った側 Sadness（石を抱えこんだ） |
| ΔE の大きな上昇・下落 | 今のまま | 今のまま（CPU の評価がアンチ向きになるので自動で正しくなる） |
| 強制パス | パスした側 Panic | 今のまま |
| 終局 | 勝者の Joy | 今のまま（勝者はアンチの判定で決まる） |

- 「隅を取られた相手が Joy」は、隅を押しつけられずに済んだ喜び、という意味づけ。
- 6x6 は損得の向きが 8x8 と同じなので、規則は変えない。

### 5.3 しきい値【Claude判断】
- 対象は `JOY_DELTA` / `PANIC_DELTA` と、優勢・劣勢のセリフに使う `ADVANTAGE_EVAL`（`constants.js:50-52`、`game-controller.js:261-263`）の3つ。どれも評価値と比べるため、評価関数の目盛りが変わると同じようにずれる。
- `JOY_DELTA` / `PANIC_DELTA` は 8x8・ふつうで統計的に決めた値（本体設計 7.3）。他の3ルールでは、`tests/tools/measure-delta.js` で同じ方法で計測する。
- 計測結果が 8x8・ふつうの値の ±30% 以内なら、共通の値を使う。外れたら、RuleSet ごとのしきい値を持つ。
- 計測結果は `.claude/docs/reports/` に記録する。

## 6. 画面

### 6.1 設定画面【Claude判断】
- 今のパネル（`makePanel` / `makeChoices`）と同じ作りで、「ルール」パネルを足す。中身は2つの選択肢の行。
  - 盤の大きさ: 「8x8」「6x6（ミニ）」
  - 勝ち方: 「ふつう（多いほうが勝ち）」「アンチ（少ないほうが勝ち）」
- 置く場所はハンデパネルの上。ハンデ欄は「8x8・ふつう」以外では隠す（2.3）。
- タップ領域 44x44px 以上など、本体設計 2 章の iOS 要件を守る。

### 6.2 プレイ画面・結果画面【Claude判断】
- 今のルールがひと目でわかるように、プレイ画面に小さな表示を出す（例: 「6x6・アンチ」）。「8x8・ふつう」のときは出さない。
- アンチの結果画面では、勝ち負けの説明に「少ないほうが勝ち」を添える。
- 盤の描画は、今の `--n` の仕組み（`ui-manager.js:572`）で 6x6 になる。石が大きくなることで崩れないかは、手動テストで確認する。

## 7. テスト

### 7.1 自動テスト（Claude が実行）
- エンジン: 6x6 の初期配置、6x6 での合法手と裏返し、アンチの `result`（少ない方が勝ち、同数は引き分け、空きマスは足さない）。
- CPU: 4つのルールそれぞれで、CPU の合法手と RuleSet の合法手が一致する。アンチの終局局面で、石が少ない側に高い値がつく。8x8・ふつうでは、直す前と同じ手を選ぶ（固定局面で比べる回帰テスト）。
- 反応: アンチの隅取り・大量返しで 5.2 の表どおりの感情になる。
- 設定: 不正な保存値で 8x8・ふつうに戻る。新しい `ruleSetId` の途中保存から再開できる。
- 既存のテスト（`tests/` 一式）がすべて通る。

### 7.2 手動テスト（ユーザーが実施し、結果を受け取るまで次に進まない）
- 4つの組み合わせで、1人用・2人用を1局ずつ最後まで遊ぶ。
- 6x6 の盤と石の見た目（PC と iOS）。
- アンチで、キャラの反応が「損得に合っている」と感じられるか。
