## 1. 目的と方針

### 1.1 何を作るか
1台の端末をみんなで同じ向きから見て遊ぶ、4人対戦モード。人間は1〜4人で、足りない分は CPU が入る。いつも4人で遊ぶ【ユーザー決定】。ルールはメガハウス「4人対戦オセロ」型（調査記録 6 章の B 案）【ユーザー決定】。

### 1.2 ゴール
- 人間1〜4人＋CPU の4人で、8x8 の盤で最後まで遊べる。
- 対象の端末は iPad・PC と iPhone の縦画面【ユーザー決定】。横向きのスマホも、今と同じく遊べる形にする。
- 石は、キャラの画像と黒・白・赤・青の色の組み合わせで、ひと目で誰の石か分かる【ユーザー決定】。
- 4体のキャラが、それぞれ自分の損得に合わせて表情を変え、しゃべる。にぎやかでもよい【ユーザー決定】。

### 1.3 非ゴール（やらない）
- 3人での対戦（余った色を中立の石として使うルール）。いつも4人なので作らない【ユーザー決定】。
- 4人対戦での 6x6・アンチ・ハンデ。盤は 8x8、勝ち方はふつう（石が多い人の勝ち）で固定【ユーザー決定（Claude の案を承認）】。
- 画面の回転（四方から囲む遊び方）【ユーザー決定】。
- CPU ごとに違う強さ。強さはまとめて1つ選ぶ【ユーザー決定】。
- 複数ラウンド制、通信対戦、4人対戦用の新しいセリフ。
- 感情の演出時間・キャラ画像の表示時間の変更。ユーザーは全ルールで少し延ばしたいと考えているが、4人対戦とは別の変更として扱う。

### 1.4 アンチゴール（動いても失敗とみなす）
- CPU どうしが組んだように、子ども（人間）1人を集中して狙う【ユーザー決定】。
- 今の 1人用・2人用（4つのルールすべて）の遊び心地や、CPU の強さ、反応の出方が変わる。既存のテストが1つでも通らなくなる。
- 石の色が見分けにくく、誰の石か迷う。
- iPhone 縦画面で、盤のマスが今より小さくなる（1マス 44px 未満になる）。
- 画面の勝敗表示と、エンジン・CPU の勝敗判定が食い違う。

## 2. ルール（2.1a 節の要約）

### 2.1 公式画像で確認した事項【調査記録】
- 4色: 黒・白・赤・青。8x8 盤。
- 初期配置（8個、各色2個）: d4=青, e4=赤, d5=黒, e5=白, d3=赤, f4=白, e6=黒, c5=青（列 a〜h・行 1〜8、標準オセロと同じ向き）。
- 着手: ほかの人の石を自分の石で挟める場所に置く。挟んだ石はすべて自分の色にする。1本の線に違う色が混ざっていても挟める（両端が自分の色であればよい）。8方向。
- パス: 挟める場所がある限り必ず打つ。無ければパスして次の人の番。
- 全滅したときの救済: 自分の色の石が盤上に0個になったら、次の自分の番で、盤上の石に隣接する（斜めも含む8方向）空きマスに1つ石を置ける。その石は、その人の次の番が来るまで、ほかの人が挟めない。
- 終局: 盤がすべて埋まったら終わり。
- 勝敗: 自分の色の石が一番多い人の勝ち。

### 2.2 アプリ独自に決めた5点【調査記録（ユーザー承認済み）】
1. 盤が埋まる前に全員が打てなくなったら、その時点で終局。
2. 一番多い石の数が同じなら同率1位。
3. 最初の手番はランダム。以降は色の順で固定して回す。
4. 守られている石が線の途中にあれば、その線は丸ごと挟めない。
5. 全滅したときの救済の石は必ず置く（置かない選択はない）。

### 2.3 本書で補う細部【Claude判断】
2.1・2.2 のどちらにも書かれていない部分を、次のように決める。2.1a 節と食い違うものは無い。
- **色の順**: 赤→白→黒→青（の繰り返し）。理由: 初期配置は 90° 回転対称で、この順が盤の上で時計回り（d3 の赤＝上、f4 の白＝右、e6 の黒＝下、c5 の青＝左）になり、子どもに説明しやすい。
- **救済の石は何も返さない**: 置いた時点で自分の色が他に無いため、挟む線ができない。
- **救済の番の判定**: 手番が来た時点で自分の色が0個なら、その番は救済の番。置けるマスは「空きマスで、8方向のどれかに石（色は問わない）があるマス」。
- **守りの解除**: 守りは「守られている石の持ち主の、次の番が始まった時点」で解ける。その番がパスでも解ける。守りが解けるのは石ごとではなく持ち主ごと（1人が持てる守りの石は救済の石1個だけなので同じこと）。複数の人の守りの石が同時に盤上にあってもよい。
- **守りの石のふるまい**: 守りの石は持ち主の色の石として、ふつうに数え、ふつうに線の端になる（持ち主が挟むときの端に使える）。2.2 の4のとおり、ほかの人から見て線の途中にあれば、その方向は挟めない。
- **「全員が打てない」の判定**: 全員について「挟める手が無い、かつ救済の番でもない」なら終局。全滅していて救済できるマスがある人は「打てる」に数える。
- **全滅して、救済できるマスも無い**: 盤が埋まっていない限り起きない（空きマスが盤上の石に1つも隣接しない状態は、石がある限り起きない）。起きたらパスとして扱う。
- **結果**: 順位は石の数の多い順。同じ数なら同じ順位（例: 12, 12, 9, 7 → 1位, 1位, 3位, 4位）。空きマスは誰にも足さない。

## 3. データの持ち方

### 3.1 エンジンを分ける【Claude判断】
- 4人用のルールは別のファイル `js/engine/four-engine.js`（名前は作る人が決めてよい）に、DOM に依存しない純粋な関数として書く。今の `reversi-engine.js` は変えない。
- 理由: 盤の値（0/±1）・手番の反転（`-turn`）・石数（黒/白）が今のエンジン全体に埋め込まれていて、混ぜると 1.4 の「今の遊び心地を変えない」を守りにくい。4人用は救済・守り・手番の順という別の状態も持つ。
- 盤は今と同じく `Int8Array`（64マス）。値は 0=空き、1〜4=色。色の数値は作る人が決めてよい。
- 状態（スナップショット、今と同じく凍結）に最低限持つもの: 盤、今の手番の色、色の順、守りの石（持ち主の色と位置。無ければ空）、手数、直前の手。
- 公開する関数の目安: 初期状態を作る、合法手（救済の番なら救済できるマス）、ある手で返る石、手を打つ（返った石と、返された石の色ごとの数を返す）、パス、救済の番かどうか、終局か、石数（色ごと）、結果（順位）。

### 3.2 RuleSet
- `js/data/rulesets.js` に4人用の RuleSet を1つ足す（id の例: `four`）。`size: 8`、`misere: false`、人数4、使うエンジンを表す値を持つ。
- 1人用・2人用の設定画面の選択肢（盤の大きさ・勝ち方）には出さない。`idFor` は今のまま。

### 3.3 GameController と保存
- `game-controller.js` は、今の p1/p2 の2枠を、席（seat）の並びとして扱えるように広げる。2人用の動作と今のテストは変えない。4人用で別の controller ファイルを作るかどうかは作る人が決めてよい。ただし、CPU の予約とキャンセル（本体設計 9.3）・自動保存・Undo の仕組みを二重に持たないこと。
- 席の情報: 席ごとに「人間（1P〜4P）か CPU か」「キャラ」「色」。
- 色の割り当ては、ゲームを始めるたびにランダム【ユーザー決定】。
- 自動保存と「つづきから」は今と同じ扱い（本体設計 9.8）。保存のキー（`otc.save.v1`）は1つのまま、4人用は新しい `version`（例: 2）で保存する。読むときは「今の版＝2人用」「新しい版＝4人用」の2つを受け付け、それ以外は今と同じく黙って捨てる。2人用の保存の形は変えない（移し替えの処理は作らない）。これで2人用の今の保存は今までどおり再開できる。

## 4. 進行（GameController）

### 4.1 手番の流れ【Claude判断】
- 最初の手番の色はランダム。以降は 2.3 の色の順で回す。
- 手番が来たら、次の順で判定する: 終局か → 救済の番か → 挟める手があるか（無ければパス）→ CPU か人間か。
- 守りの解除（2.3）は、手番の持ち主が守りの石を持っていたら、その番の始めに行う。
- パスの表示・パス音・タップでの早送りは今と同じ（本体設計 9.4）。
- CPU の1手の時間（考え中の演出、`CPU_MIN_WAIT_MS`）は今のまま【ユーザー決定】。CPU が3体いると人間の番まで数秒待つが、それでよい。

### 4.2 Undo / Redo【Claude判断】
- 人間が1人: 今の 1人用と同じく「人間の番で、人間が打てる（挟める手か救済）状態」まで戻す。CPU の手とパスはまとめて戻す。
- 人間が2人以上: 「直前の人間の番（どの人間でもよい）」まで戻す。CPU の手とパスはまとめて戻す。Redo はその逆。
- 戻した先が CPU の番になる場合（CPU が先手の初手前など）は、今と同じく初期状態まで戻し、CPU の思考を再開する。
- 戻したあとは、全員の感情を Normal にし、反応は出さない（`replay: true`）。今と同じ。

### 4.3 アシスト【Claude判断】
- 今と同じ設定で、人間の番に最善手を示す。救済の番は、救済できるマスの中から最善のマスを示す。

## 5. CPU

### 5.1 方針
- 新しいファイル `js/engine/four-ai.js`（名前は作る人が決めてよい）に書く。今の `reversi-ai.js` は変えない。理由: 今の CPU は2人のゼロサム探索（negamax）で、4人には使えない。
- **集中攻撃をしない**（1.4）【ユーザー決定】: 各 CPU の評価は「自分の石と位置」だけで決める。ほかの人の誰の石を取るかで、えこひいきしない（人間かどうかも見ない）。人間の席かどうかの情報を CPU に渡さない。
- 探索のやり方【Claude判断】: max^n（各手番の人が自分の評価を最大にすると仮定して読む方法）を使う。調査記録には MCTS-maxn が強いとあるが、子ども向けにそこまでの強さは要らず、手が決まりやすくテストしやすい方を選ぶ。読みの深さや枝の刈り方は作る人が決めてよい。
- 強さ（やさしい／ふつう／つよい）は今と同じ3段階。全員まとめて1つ【ユーザー決定】。目安【Claude判断】: やさしい＝1手先だけを見て、ときどきランダムに打つ。ふつう＝1周（4手）先まで。つよい＝ふつうより深く、時間の許す限り。1手の考える時間の上限は今の各段階（`constants.js` の `AI_LEVELS` の時間）を超えない。
- UI を固めない仕組みは今と同じ（本体設計 6.4。メインスレッドで少しずつ探索し、キャンセルできる）。
- 救済の番も CPU が自分で救済のマスを選ぶ。

### 5.2 合格条件【Claude判断】
自動対局（Node のツール。今の `tests/tools/measure-strength.js` と同じ形）で確かめ、結果を `.claude/docs/reports/` に記録する。
- 強さの順: 「つよい1体＋やさしい3体」で、つよいの平均順位がやさしいより良い。「ふつう1体＋やさしい3体」でも同じ。席と色はランダムにして、数十局以上を回す。
- 集中攻撃をしない: 「人間の代わり」の席（やさしい CPU）を1つ決め、ほかの3席を同じ強さの CPU にして対局する。CPU が打った手ごとに「返した石のうち、人間の代わりの石だった割合」と「盤上の自分以外の石のうち、人間の代わりの石の割合」を比べ、前者の平均が後者の平均の 1.2 倍を超えないこと。1.2 という数は目安で、超えたら評価を見直す。

## 6. キャラクターの反応

### 6.1 方針【ユーザー決定】
4体それぞれが、自分の損得に合わせて反応する。1手で何体も反応してにぎやかになってもよい。

### 6.2 具体的な規則【Claude判断】
今の発火条件（本体設計 7.2）を、4人では次のように読み替える。優先順位は今と同じ（Anger ＞ Panic ＞ Sadness ＞ Joy）。

| 条件 | 対象 | 感情 |
|---|---|---|
| 隅を取った | 打った人 | Joy |
| 自分の評価が大きく上がった（ΔE ≥ `JOY_DELTA`） | 打った人 | Joy |
| 自分の評価が大きく下がった（悪手、ΔE ≤ −`PANIC_DELTA`） | 打った人 | Panic |
| その手で自分の石が `SADNESS_FLIPS` 個以上返された | 返された人（それぞれ） | Sadness |
| 自分の石が全滅した | 全滅した人 | Panic |
| その手で自分の評価が大きく下がった | 打っていない人（それぞれ） | Panic |
| 強制パス | パスした人 | Panic |
| 救済の石を置いた | 置いた人 | Joy |
| 終局 | 1位の人（同率なら全員） | Joy（セリフは win） |
| 終局 | 2〜4位の人 | Sadness（セリフは lose）。今の2人用で負けた側と同じ |

- 「隅を取られた相手の Anger」は4人では使わない。理由: 2人と違い、隅を取られて誰が損をしたかが決まらない。
- ΔE は、それぞれの人について、自分の評価の「打つ前→打った後」の変化。4人の評価はゼロサムではないので、人ごとに計算する。計算の重さが CPU の時間を圧迫しないこと（浅い評価でよい）。
- しきい値（`JOY_DELTA` / `PANIC_DELTA` / `ADVANTAGE_EVAL`）は、4人用の評価の目盛りで、`tests/tools/measure-delta.js` と同じ方法（自動対局の ΔE 分布の上位約10%）で計測し、4人用の RuleSet の `thresholds` に持たせる。結果は `.claude/docs/reports/` に記録する。
- 優勢・劣勢のセリフ（winning / losing）: 各人の自分の評価値で順位を付ける。評価が一番高い人が2番目の人より `ADVANTAGE_EVAL` 以上高いとき、その人に winning。評価が一番低い人が下から2番目の人より `ADVANTAGE_EVAL` 以上低いとき、その人に losing。同じ値で並んだら言わない。同じキャラで `ADVANTAGE_COOLDOWN_MOVES` 手に1回まで（今と同じ）。`ADVANTAGE_EVAL` の初期値は、今の RuleSet と同じく計測した `JOY_DELTA` の値にする。
- セリフは今の状況の種類（`lines`）をそのまま使う。新しいセリフは足さない。パネルの表情と吹き出しは、4体それぞれに出してよい（にぎやかでもよい、の意味はここ）。
- 全画面の演出とリアクション音は、今と同じく1手に1つだけ出す（`effects.js` の作りは変えない）。どの感情を出すか: 人間が1人なら、今の1人用と同じく人間の感情だけ。人間が2人以上なら、人間の感情の中から今の2人用と同じ優先順位で1つ選ぶ。CPU の感情は全画面には出さない。終局は今と同じく勝者（1位）の Joy。

## 7. 画面

### 7.1 設定画面【Claude判断（ユーザーが案を承認）】
- 遊び方の選択に「4にんで あそぶ」を足す（今は「ひとり」「ふたり」）。モード名に商品名（「4人対戦オセロ」）は使わない。
- 「にんげんは なんにん？」で 1〜4 を選ぶ。1P から順に、人間がそれぞれキャラを選ぶ（同じキャラは選べない。今の選び方と同じ作り）。
- 残りのキャラが CPU になる。4体全員が出るので、「CPU を引き直す」ボタンは出さない。
- CPU が1体以上いるときだけ「CPU のつよさ」を出す。
- 盤の大きさ・勝ち方・ハンデ・先手の欄は隠す（盤 8x8、ふつうのルール、最初の手番はランダム）。
- 色はスタート時にランダムで決める。プレイ画面の最初に、誰が何色かを見せる（例: 「くちぱっちは あか」）。見せ方は作る人が決めてよい。
- 前回の設定（人間の人数とキャラ）を今と同じく覚えておく。

### 7.2 プレイ画面のレイアウト【ユーザー決定（A案）】
- iPhone の縦画面: 上に2人、盤、下に2人、操作ボタン。パネルは今の半分の幅で、横に2つ並ぶ。盤は今と同じ大きさ（画面の幅いっぱい）を守る。
- iPad・PC など横長の画面: 盤の左に2人、右に2人を縦に並べる。
- 席の置き方【Claude判断】: 色の順（赤→白→黒→青）に、左上→右上→右下→左下（時計回り）に並べる。手番が時計回りに光って移ることで、次が誰か分かる。
- 手番の人のパネルは、今と同じく拡大＋光る枠。
- パネルには、キャラ画像（今の感情）、名前、色の印、石数、手番の印、吹き出し。CPU なら CPU と分かる印。
- 本体設計 2 章の iOS 要件（タップ領域 44px 以上、safe-area など）を守る。390x844 の縦画面で、盤のマスが 44px 以上あること（今の見積と同じ。パネルの高さを今より増やさない）。

### 7.3 石の見た目【ユーザー決定（細部は Claude判断）】
- 石は、その色の持ち主のキャラ画像と、黒・白・赤・青の色の組み合わせで見せる。色は、輪っかや背景など、画像の外側にはっきり出す。色の付け方の細部は作る人が決めてよい。合格の目安は「子どもが迷わず誰の石か言える」こと（手動テストで確かめる）。
- 今の石は「表と裏に2人のキャラ」を貼って裏返す作り。4人では返った先の色が毎回違うので、裏返す途中で絵と色を差し替えるなどの方法にする。置いた位置からの距離順に少しずつ遅らせて返す演出（`FLIP_STAGGER_MS`）は今と同じ。
- 2人用の石の見た目は変えない。
- 救済の番: 救済できるマスを、今のアシストや合法手の表示と同じような印で光らせる。
- 守られている石には、小さな印（例: 盾や鍵のマーク）を付ける。守りが解けたら消す。

### 7.4 結果画面【Claude判断（ユーザーが案を承認）】
- 1位〜4位を、キャラ・色・石の数と一緒に並べる。同じ数なら同じ順位。
- 1位のキャラ（同率なら全員）が喜ぶ（6.2）。
